# Phase 4 — Functional simulator lookup

Status: implementation ready for the Mac checkpoint. The cloud workspace is
Linux and cannot build Apple frameworks, run Vision, or launch an iOS simulator.
Phase 3's six Mac tests passed before these changes. Phase 5 remains paused.

## Behavior

The existing direct-match pre-processing now works when the knowledge resource
is ready, independently of Llama or the category classifier. It uses the original
comma/parenthesis parser, basic-ingredient exclusions, exact substance/alias
matching, and color/flavor mappings. Duplicate matches to one substance collapse
to one result. The original LLM identification and embedding-retrieval path stays
available when a real local model has loaded; its prompts, generation parameters,
query features, and threshold are unchanged. Arbitrary unmatched ingredients are
not sent to approximate embedding search in the direct-only mode.

The result screen identifies direct-only analysis. An empty match list says that
no matching records were found, rather than claiming the food has no additives.
Category prediction and generated explanations remain unavailable without their
models. Real stored technical effects and sourced CFR links are usable offline;
opening external CFR pages needs connectivity. The original special-case flavor
mappings remain in use; their existing descriptions are not generated by Llama.

The original Example and entry-ID functions are accessible alongside Random
Sample. IDs 0–19 refer to the bundled sample array. Editing ingredients clears
prior results/category selection and sampled-product context. Analysis, OCR,
classification, and explanation work disable competing input changes. Reset
clears results. Saved results retain the existing history fields and stage names,
with a summary that records whether direct-only or AI identification was used.

The iPhone-name/number gate no longer blocks lookup. MLX eligibility uses build
configuration, destination, and Metal availability, with actual model loading
still required. Simulator builds never initialize MLX; availability of a Metal
device alone is not proof of working inference or adequate memory.

Knowledge loading now uses typed decoding and validates the original 384-dimension
contract, record counts, uniqueness, finite values, and normalization. Missing,
malformed, zero-dimensional, or incompatible data leaves lookup unavailable with
an error, rather than force-casting or enabling invalid searches.

Choose Photo uses Apple's scoped photo picker, which does not require access to
the user's entire library. Cancel leaves ingredients unchanged. Camera requests
permission before presentation and explains denied/restricted access; simulator
camera unavailability falls back to photo selection. Vision runs away from the
main actor, uses an image with orientation applied, and reports unreadable,
no-text, and recognition failures while clearing the processing state.

Save and delete failures display errors. Failed inserted results are discarded;
a failed history deletion rolls back. UI history tests use separate UUID-named
SQLite files in the app's temporary directory through a Debug-only launch
environment variable, leaving normal user history untouched.

their recorded bytes. Swift grammar parsing passes; this does not type-check
Apple APIs. Source bundle and model data are unchanged. Existing project test
membership includes the added tests without project/package changes.
